# cube 项目现状

> 本文件是 cube 项目的**事实快照**——描述当前代码「是什么」，基于代码现状反向提取。
> 与 [`../proposals/`](../proposals/) 的关系：本文件是「现状」，proposals 是「未来要做什么」。
> 维护节奏：每次合并一个有意义变更后同步更新。与代码冲突时以代码为准。

---

## 一、定位

**cube** —— 面向个人开发者的本地项目管理工具（CLI 优先 + 本地 Web）。Go 1.26 编写，module path `cube`。

- 历史有三代：v1 (php)、v2 (go)、**v3 (当前)**。
- 出口：CLI（人用 / alfred）、本地 Web HTTP server（`cube server`，huma + 标准 ServeMux）。MCP 出口为后续规划。
- 定位原则：不做云服务、不绑 AI（cube 可被 AI 编排，但自身不集成 AI）。

---

## 二、分层架构

```
基础设施  config / logger / version                                    所有层共享
能力      opener / util(git / fuzzy / easycache / pathkit / slicekit / iconkit / store / tui)  通用动作, 不含业务实体
领域      project (含 gitcache / scan / clone) / usage / workbench        业务 domain, 含实体和规则
出口      cmd / handlers / web / serve                                 把领域包成 CLI/Web；handlers 是业务 HTTP handler 层，web 是服务端框架；serve 管 server 进程（fork/探活/关停）
装配      app / main                                                  接线
```

**依赖纪律**：基础设施不依赖上层；能力层只依赖基础设施；领域层依赖能力+基础设施；`handlers` 依赖领域层与 `web` 框架；**cmd 与 web 不互调**；`serve` 依赖 `web`（复用 shutdown 鉴权 header/token）；`app` 是唯一接线点（`app.New(cfg)` 构造整个 App）。

**扩展模型**：加一个新 domain = ①领域包 ②`cmd/<x>` 子命令组 ③`handlers/` 加 `<domain>_handler.go` ④config 加节 ⑤`app/app.go` 装配清单加构造。五处都是加法，不碰现有 domain。

## 三、关键机制

### 3.1 项目前提：所有项目都是 git 项目

`.git` 存在是扫描判定项目的必要条件（详见 `project/scan.go`）。因此 `tags` 不打冗余的 `git` 标签，只标额外特征（`worktree` / `godot`）。

### 3.2 gitcache 定时刷新

git 项目信息（分支/ahead-behind/dirty 等）缓存在 `~/.config/cube/cache/git.json`。读命令从缓存读快照（几乎零开销），**读路径不阻塞、不触发采集**。

刷新机制按进程类型区分：

| 进程 | 读 git.json | 触发刷新 |
|---|---|---|
| **server**（常驻） | 启动时 Load 一次 | 进程内 goroutine `time.Ticker` 定时 `Refresh`（默认 5 分钟）→ 写内存 + flush git.json |
| **CLI**（短命） | 启动时 Load 一次 | **不刷新**，只读启动时 Load 进来的快照 |

机制要点（`project/service.go` + `project/gitcache/cache.go`，重构记录见 [`docs/proposals/archived/1004-gitcache常驻化重构/`](../proposals/archived/1004-gitcache常驻化重构/)）：
- **server 定时器**：`Service.StartRefreshTicker` 起 goroutine 跑 `time.Ticker`，启动即刷一次（避免冷启动空窗），之后定时刷新。刷新 = 重扫项目列表（`scanCache.Reload`，毫秒级）→ 按最新路径列表整表采集 git（`gitCache.Refresh`，数十秒级）→ 落盘；`scanUpdatedAt` / `gitUpdatedAt` 分别记录两类数据的新鲜度（web list/info 接口返回，前端分别判断）。装配点在 `cmd/server/start.go`（`app.StartBackgroundJobs` → `server.Start` → `app.StopBackgroundJobs`），CLI 装配不调。
- **单写者模型**：server 是 git.json 唯一写方，CLI 只读不写，无跨进程并发写。落盘靠 `Save()` 的原子写（`util/store.WriteFileAtomic`，tmp + rename），无需 flock。
- **git.json 角色**：跨重启持久化缓存——server 重启后秒恢复，CLI 读最近一次落盘（server 没跑时快照可能略旧）。
- **降级优先**：定时器 goroutine 内 recover，采集异常不拖垮 server 进程。
- **采集可观测**：每次 `Refresh` 完成写一条汇总日志（项目数/成功/失败/开始/结束/耗时），排查「缓存为何没更新 / 采集耗时异常」直接查 `app.log` 这一条。
- **CLI 触发例外**：`cube dev refresh-gitcache`（Hidden 调试命令）可手动触发同一路径的刷新（重扫 + 采集 + 落盘），供开发期实测采集耗时；业务 CLI 命令仍严格只读。

### 3.3 opener：接口化 + settings.json + icon

`Opener` 是接口（`opener/opener.go`：`Name/Title/Roles/Icon/Summary/Open(role, slotArgs...)`），唯一实现 **`execOpener`**（`opener/exec.go`）：命令模板形态，能力由 `roles []Role` 声明（`open-dir`/`open-file`/`diff-dir`/`diff-file`，见 `opener/role.go`），`slotCount` 由 role 推导（1 或 2，同 opener 所有 role 必须一致）；`cmd` 用 `$0/$1...` 占位符引用路径槽位，无占位符时路径追加末尾；cmd[0] 自引用替换（`resolveBin`）：为 `cube` 或以 `/cube` 结尾时换成当前进程可执行文件（`os.Executable`，失败降级保留原值）——opener 组合 cube 自身 CLI（如 `["cube","ui","workbench","$0"]`）不依赖 PATH、与当前进程同源；经 `Executor` 执行（`opener/executor.go`），默认走 `os/exec`，测试注入 fake。

`Open` 带 role 首参，role 校验收敛在实现内（不支持即中文错误），调用方无需再核对。`Title()` 展示文案（如「打开所在目录」），Spec 可配 `title`，缺省生成「用 {name} 打开」。`icon` 声明只判别渲染方式（`lucide` 图名 / `image` base64 PNG），未配置时解析 Spec 阶段填默认 lucide 图（app-window-mac），**对外永远有 Icon**。icon 声明语义（`Icon` 类型 / 类型枚举 / `ValidateIcon`）共享在 `util/iconkit`（跨领域：opener / scanRules 等共用；nil = 可选语义，默认值策略归各域），`.app → icns → PNG` 提取也在 iconkit（缩放 ≤64px）。

**「打开工作台页」不设独立 opener 形态**（曾实现 webOpener 后拆除）：URL 拼接（端口/路由/转义）收敛在 `cube ui workbench <path>` 命令（`cmd/ui/workbench.go`），配置 exec opener `["cube","ui","workbench","$0"]` 即可；Web 前端的「在工作台打开」入口是应用内路由跳转，独立于 opener 体系。

**opener 数据存 `settings.json` 的 `openers` 节**（与 config.json 切割——运行中可变更的用户可管理数据）。`settings` 包（基础设施，与 config 平级）提供节级 API：`LoadSection`（一切读失败降级为空）、`SaveSection`（锁内读-改-写 + 临时文件 rename 原子写，坏 JSON 拒写）、`HasSection`；其他节语义级透传（值不变、格式随统一缩进规范化）。`opener.Service` 每次**直读不缓存**（Web 保存即生效）；条目级坏数据跳过不阻断；写侧（`SaveOpener`/`DeleteOpener`/`ReorderOpeners`）先走领域构造校验，坏数据中文错误不落文件。迁移未做代码（用户手动 jq 迁移）。

### 3.4 App 装配

`app.New(cfg)` 一次性构造整个 App（`app/app.go`）：构造各 service + 组装 web server。`cmd.Execute()` 在 main 里调用，把 `*app.App` 显式传给所有命令工厂。**无全局单例、无懒初始化**。

**service 生命周期钩子**（`app/hooks.go`，可选实现，app 层用类型断言分发，未实现即跳过）：

- `OnServerStart()` / `OnServerStop()`：常驻 server 启停后台任务（`app.StartBackgroundJobs` / `StopBackgroundJobs` 分发）。project 定时刷新、usage 启动 compaction 挂在这两个钩子上；CLI 短命进程不调用。

### 3.5 配置与环境分离

**dev / prod 双环境**（见 [`docs/proposals/archived/1026-环境分离/`](../proposals/archived/1026-环境分离/)）：环境身份由 `version.IsDev()` 推导——二进制被 ldflags 注入了正式 version（`make build` / `make install`）即 prod，无注入（源码直跑、air、run.sh）即 dev。默认配置目录随之分流：dev → `~/.config/cube-dev/`，prod → `~/.config/cube/`。跨环境数据不做工具迁移：config 人工 diff 合并，usage 记录各自独立积累。

`config.json` 按 domain 分节。`--config` 指定 config.json **文件路径**（优先级最高，dataDir 缺省取其所在目录），`--debug`（`-D`）开 debug（只影响 logger 初始化）。配置文件缺失降级为默认值；JSON 解析失败报错退出。**无热 reload**（已移除，转向命令式改 config，`config.Save` 提供原子写）。

### 3.6 server 进程管理（HTTP 模式）

server 的进程管理（探活、关停）走 **HTTP 应用层**，不依赖 pid 文件、信号、系统守护。设计背景见 [`docs/proposals/archived/1001-server后台常驻与HTTP管理/`](../proposals/archived/1001-server后台常驻与HTTP管理/)。

- **探活**：`serve.Status(port)` GET `/api/system/whoami`，验证返回 `app=="cube"` 才算 cube server 在跑（防「别的服务恰好占同端口」误判）。
- **关停**：`serve.Stop(port)` POST `/api/system/shutdown`（带 HMAC 时间戳鉴权，5s 窗口防重放）→ server 自发 SIGTERM → `web.Server.Start` 的信号监听走 graceful shutdown。和 Ctrl+C 同路径。
- **后台启动**：`serve.Fork()` fork 自身跑前台 `cube server start`（子进程自己读 config 端口，与父进程同源），setsid 脱终端、stdio 丢弃（接 /dev/null，日志走子进程自己 `logger.Init`）。**不写 pid 文件**。
- **端口单一事实源**：config 的 `server.port`（dev `6001` / prod `6101`，由各环境配置目录自带）。**不再支持多端口多实例、无 `-p` flag**——md/status/stop 等依赖 server 的命令一律读 config 端口，从根上杜绝「传了自定义端口被遗忘」的孤儿实例。常驻形态：prod 走 launchd LaunchAgent（`com.heyuuu.cube`），dev 走 air。
- **不做 lazy 拉起**：依赖 server 的命令（未来的 md 等）只探测、不自动起，server 由用户显式 `cube server start` 启动（nginx 模式）。

### 3.7 git 访问层：读/写统一走原生 git

`util/git` 是唯一的 git 访问层（历史：v3 早期读走 go-git 库、写走系统 git，双轨；已统一为原生 git）。原因：go-git 的 Status 不加载全局忽略链（与真实 git 输出有偏差）、忽略过滤发生在全量 diff 之后导致大仓库秒级卡顿；原生 git 行为与用户日常 git 完全一致且自带 index 缓存。原「避免 CLI 批量采集 fork 开销」的动机随 gitcache 异步采集（3.2）消失。

- **封装边界**：包外只调用类型化函数，缺什么在包内新增封装（含输出解析，返回类型化的 struct/切片/集合）；不 exec git、不拼子命令参数、无「调用方传 args 的通用执行口」（曾有 `RunRead`，已移除）。平台/环境兼容（quotePath 转义 / locale / pager / `diff --no-index` 退出码 / 忽略目录折叠语义）单点收敛在包内。规则见 AGENTS.md 第 14 条；测试 fixture 除外。
- **写操作**（`git.go`，Clone/Push/Commit 等）：stdio 透传，用户看到 git 真实输出。
- **读操作**按主题分文件（共享执行核 `run.go` 的 runOut/isGitRepo）：`refs.go`（Refs/BuildRef/HeadRef/CurrentBranch/DefaultBranch/AheadBehindRemote/HeadSha 等 ref 查询，ref 统一为 `Ref` 值对象——Name/ShortName/Remote/Branch + 谓词）、`remote.go`（Remotes/RemoteUrl，remote 配置查询）、`status.go`（LoadRepoStatus/LoadIgnored 等状态派生，dirty 即 LoadRepoStatus().Dirty，逐文件明细即其 Files）、`tree.go`（ListFiles/ListFilesUnder/FileShasAtRef/ReadFileAtRef/ExistsAtRef）、`diff.go`（DiffFiles/DiffNoIndex/Numstat）、`log.go`（CommitsPage）、`worktree.go`（WorktreeList）。只解析机器可读输出（`for-each-ref --format` / `remote -v` / `status --porcelain=v2`（含 `--ignored`）/ `rev-list --count` / `symbolic-ref` / `ls-tree -z` / `diff --name-status -z`），不解析任何随 locale 翻译的 stderr 文案。
- **输出稳定化**（`runOut` 统一注入）：`LC_ALL=C` + `GIT_PAGER=cat` 环境变量、`--no-optional-locks`（后台读不抢 index.lock）、`-c core.quotePath=false`（中文路径不转义八进制）；status 显式 `--untracked-files=normal`（覆盖用户 `status.showUntrackedFiles=no`）。
- **非仓库判定**：`isGitRepo` 用 `os.Stat(.git)` 预判——git 报错文案随 locale 变化不可解析，靠预判把「非仓库」（零值降级）与真实错误区分开。
- **错误约定**（原 gogit 包延续）：业务空值场景（非仓库/缺 remote/缺分支）返回零值 + nil；真实读取错误返回 error。gitcache 与 cmd 层依赖此约定。
- **版本基线**：`symbolic-ref` / `for-each-ref --format` 等要求 git ≥ 2.22（2019+，实际开发机 2.29 验证通过）。

### 3.8 工作台（workbench）

git 可视化工作台（取代 SourceTree 的定位），需求群 1008/1010-1015 已全部交付归档（各提案 README 有验收记录与实现更新）。**解耦 project scan**——入口是任意本机 git 目录，不要求被 cube 管理。
- **TreeSource 统一抽象**（`workbench/types.go`）：`{type: commit|ref|worktree, id}`，前后端统一用单参数序列化 `type://id`（如 `ref://main`、`worktree:///path/to/dir`），`ParseTreeSource` 校验（commit 须 40/64 位 sha、ref 短名按 check-ref-format 核心规则挡 rev 表达式）。
- **git 信息不走 gitcache**：工作台所有 git 读直接调 `util/git`（实时性与内容范围不同，不混用）；读路径无缓存，实时性由前端 React Query 的 staleTime 控制。
- **面板体系**（前端 `web/src/pages/workbench/`）：注册表面板仅 `git-tree` + `content` 两类（原 code/diff/auto 三面板已合并）。`content` 面板为 `current [+base]` 视图模型——URL 参数 `current`（当前查看的版本）+ 可选 `base`（对比基准），diff 方向固定 base → current，base 缺省 = 相对基准（worktree→HEAD、ref/commit→父提交）。公共组件：`SourcePanelShell` / `FileTreePane`（树列 + 视图偏好 localStorage）、`FileContentArea` / `useFileEditing`（单文件 CodeMirror / diff 双栏双模式 + 确认式轻编辑）。布局（面板槽位/宽度/收窄）存 localStorage `cube.workbench.layout`，旧布局 id 自动迁移。
- **唯一写路径**：`POST /api/workbench/file/save`（仅 worktree 源，内容未变跳过，不做任何 git 操作）；路径安全靠 `secureJoin`（显式拒绝 `..` 段 + Clean + 前缀校验）。
- **PTY**（`workbench/pty.go`）：`GET /api/workbench/pty` WebSocket（huma 外原生 mux），JSON 帧 input/resize（入）、output/exit（出）；每连接起 `$SHELL` 子进程（creack/pty），断开杀进程；server 停机经 `OnServerStop` 钩子回收全部会话。前端多终端 = tab + 横向分屏，偏好（字体/字号/高度）localStorage。
- **安全边界**：接口可读任意本机 git 目录 / 开本机 shell，localhost 无鉴权服务是 cube 现状，MVP 接受此边界（总纲定稿）。

### 3.9 scan/clone 规则：settings.json 分节直读（提案 1029）

scan/clone 规则数据源是 settings.json 的 `scanRules` / `cloneRules` 两个数组节（原 config.json `project` 节已移除，残留不读取；存量由用户手动迁移，同 opener 先例）。`project.Service` 对规则**直读不缓存**（`loadScanRules` / `loadCloneRules` 加载即转换校验：`~/` 展开、坏路径降级跳过），Web 保存即生效。写侧（`SaveScanRule` / `DeleteScanRule` / `ReorderScanRules` 及 clone 对应方法，`project/settings.go`）校验收敛在写边界，坏数据中文错误不落文件；scan 规则的 save/delete/reorder 成功后立即重扫项目列表（毫秒级）。scan 规则键 = `path` 原串（编辑 path 等价删旧存新），clone 规则键 = `repoHost`+`repoPrefix`。icon 声明语义共享自 `util/iconkit`（见 3.3）。

### 3.10 文件存储原语：util/store（提案 1033）

`util/store` 收敛文件存储通用原语（只依赖标准库，路径由调用方给定，无环境副作用；按主题分文件 atomic / json / jsonl，主题间无依赖）：

- `WriteFileAtomic`（atomic.go）：tmp 同目录 + rename 原子写（rename 原子性只在同文件系统成立，故 tmp 必须落目标同目录），目标目录不存在自动递归创建，中途失败清理 tmp。
- `SaveJson` / `LoadJson`（json.go）：缩进 + 尾换行（存储文件常被人工翻看）；`LoadJson` 对文件缺失返回哨兵错误 `ErrFileMissing`，调用方据此时降级（区别于读失败/解析失败）。
- `AppendJsonl` / `LoadJsonl` / `IterJsonl` / `IterJsonlReverse`（jsonl.go）：O_APPEND 单行追加、全量读（坏行跳过并 slog）、正向/逆向流式逐行迭代（`iter.Seq2[行号, T]`，随时 break 停止；逆向为分块从文件尾扫描、不整读文件，行号是物理行号）。

存量消费方：gitcache `Save`（`WriteFileAtomic`）、config `Load/Save`（`LoadJson`/`SaveJson`）、settings `readDoc/saveDoc`（`LoadJson`/`SaveJson`）——三处手写原子写已全部收敛至此。1034 的 usage JSONL 存储也以此为基础。

## 四、命令列表

入口 `cmd/root.go`，根命令 `cube`。全局 flag `--config`（config.json 文件路径）/ `--debug`（`-D`）用 Go 原生 flag 在 cobra 初始化**之前**预解析（`extractGlobalFlags`）；cobra 上的同名 flag 仅用于 help 提示。

| `diff <path1> <path2> [-o OPENER]` | 用对比工具对比两个路径 |
| `push [仓库路径]` | 批量推送分支/tag 到多 remote |
| `pull [仓库路径]` | 从单个 remote 批量快进更新本地分支（多 remote 时交互单选；当前分支 `pull --ff-only`，其余 `fetch 分支:分支` 快进；默认勾选远端领先分支） |
| `check <options>...` | 检查项目（clone-rules / git-dirty，不传检查全部） |

### 组命令

- **`server`** — 管理 Web HTTP server 的生命周期（进程管理走 HTTP API，详见 3.6）
  - `start [-d|--detach]` — 启动 server（端口读 config `server.port`）。默认前台阻塞（Ctrl+C 退）；`-d` 后台 fork 脱终端
  - `stop` — 触发后台 server 平滑关闭（POST `/api/system/shutdown`，HMAC 鉴权）
  - `status` — 探活（GET `/api/system/whoami`），表格输出状态/端口/版本/访问地址
  - 裸跑 `cube server` = `cube server status`（查看状态比启动高频）。单环境单实例，端口唯一来源于 config。
- **`web`** — 用浏览器打开 cube Web UI（依赖 server 在跑，未跑时报错提示先 start，不做 lazy 拉起）
  - 裸跑 `cube ui` — 打开首页（`ServerURL()`）
  - `md <path>` — 以 Web 方式打开 markdown 文件或目录（原一级命令 `cube md` 迁入；拼 `/md?path=<abs>` 交前端渲染）
- **`alfred`**（Hidden）— Alfred workflow 集成，输出 Script Filter JSON
  - `project-search {query?}` — 搜索项目
  - `project-open <project-name>` — 打开项目
  - `opener-search [query]` — 搜索 opener
- **`dev`**（Hidden）— 内部调试命令
  - `tui [component]` — 演示 tui 组件
  - `commands` — 列出所有命令
  - `logger` — 测试 slog 输出
  - `refresh-gitcache` — 手动触发 gitcache 全量采集（重扫项目 + 刷新 git.json，实测耗时）

## 六、数据模型

### 6.1 Project 域（`project/`）

- **`Project{path, group, name, tags}`** — path 是绝对路径主键，name = `group:subpath`。git 状态不入实体，由 `Service.GitInfo(path)` 查 gitcache 快照补出。
- **`ScanRule{Group, Path, MaxDepth, Icon}`** — 扫描规则（Icon 可选）。存 settings.json `scanRules` 节，加载即转换校验（`~/` 展开、坏路径降级跳过），详见 3.9。
- **`CloneRule{RepoHost, RepoPrefix, LocalPath}`** — clone 路由规则，按 host + path 前缀匹配，多条取 prefix 最长者。存 settings.json `cloneRules` 节，键 = host+prefix。
- **`gitcache.Entry{RepoUrl, CurrentBranch, DefaultBranch, Branches, Ahead, Behind, Dirty, WorktreeMain, CollectedAt}`** — git 状态快照。

### 6.2 Opener 域（`opener/`）

- **`Opener` 接口**（`Name/Roles/Icon/Summary/Open`）：唯一实现 `execOpener{name, cmd, roles, slotCount, icon, executor}`（cmd 用 `$0/$1` 占位，slotCount 由 roles 推导）。
- **`Spec`** — settings.json openers 节的存储形状（name/title/cmd/roles/icon）。
- **`Role` 枚举**：`open-dir`/`open-file`（slotCount=1）、`diff-dir`/`diff-file`（slotCount=2）。
- **`Icon{type: lucide|image, value}`** — 图标声明（`util/iconkit` 共享类型，opener 持别名），零值未配置（前端 fallback）。

### 6.3 Usage 域（`usage/`，JSONL 文件存储）

统一的项目使用记录：一次「使用」= 一次 opener 打开事件，所有打开入口（Web `opener/open`、CLI `cube open`、alfred `project-open`）在打开成功后追加一条（`open_path` 按路径直开**不记**——目标可能不是项目，脏 key 永不过期会污染排序信号；Web `opener/open` 只在打开目标是已收录项目时记录）。

**记录**（`Record`，JSONL 行，文件 `dataDir/state/usage.jsonl`、**不放 `cache/`**——它参与排序语义）：

```json
{"time":"2026-08-27T21:03:14+08:00","project":"/Users/heyu/Code/heyuuu/cube","opener":"idea","dir":"/Users/heyu/Code/heyuuu/cube--web/server"}
```

- `time`：RFC3339，行序与它单调一致，承担排序职责（追加不变量：行序 = 时间序）；
- `project`：主项目**绝对路径**（project 的唯一标识，排序 join 用它；worktree / monorepo 子目录打开时也恒记主项目路径，归并键不分裂）；
- `opener`：opener 名；
- `dir`：实际打开的目标目录绝对路径（主项目根打开时省略；worktree / workspace 子目录时为其绝对路径，1030/1032 落地后开始写入）。字段演进约束：只增不改（新字段加 `omitempty`），读取方容忍缺失字段（无 schema 前后向兼容）。

**读写原语走 `util/store`**（1033）：追加 `O_APPEND` 单行（POSIX 小块 append 原子，CLI 短进程与常驻 server 并发追加安全，全程无 flock）；读侧全量读 + 内存去重（同 key 留更新行）：

- `LatestByProject() map[path]time`：项目列表最近使用置顶排序（最近 10 条置顶、其余原序）与 `lastUsedAt` 展示；
- `LatestOpeners(project, limit)`：alfred 的 opener 排序偏好（同项目常用 opener 靠前）。

**清理**：server 启动时 `OnServerStart` 钩子异步 compaction 一次——tmp+rename 整体重写，每个 `(project, opener, dir)` 组合留最新一条 + 30 天内记录（重写瞬间并发 append 的极少数记录会丢，usage 是 best-effort 信号，接受）。保留期常量 `retentionDays = 30`（不进配置文件）。历史 sqlite 数据**未迁移**（旧表只有 alfred 记录，价值低，新文件从空开始）。

> gorm + sqlite 依赖已随本域落盘方案移除（`db` 包、`data.db`、AutoMigrate 接线均已删除）。

### 6.4 Workbench 域（`workbench/`）

**无持久化实体**（不入 sqlite/config），纯运行期编排：类型定义（`TreeSource` / `WorktreeStatus` / `DiffEntry` / `FileResult` 等）+ Service 方法（Info/Refs/Commits/WorktreeStatuses/Tree/ReadFile/SaveFile/DiffTrees/ReadFileDiff/Changes/ServePty）。文件布局遵循 Service 包布局规则：`service.go`（Service struct + 全部方法）/ `types.go` / `file.go` / `diff.go` / `pty.go` / `helpers.go`。

## 九、已知 gotcha

- go 源码根在 `server/`（不是仓库根），module path 是 `cube`（README 里写的 `github.com/heyuuu/cube` 是旧值，以 go.mod 为准）；`go build` / `go test` / `goimports` / `go vet` 都要在 `server/` 下跑。
- `.gitignore` 内：`tmp`（构建产物）、`runtime`（测试产物）、`server/web/ui`（`make build-ui` 从 `web/dist` 拷贝后 go:embed 嵌入，改前端改 `web/` 不要直接改它）、`web/openapi.json`（本地生成）、`.zcode/plans` 等 plans 目录。
- 默认配置目录按环境分流：dev `~/.config/cube-dev/`、prod `~/.config/cube/`（非项目目录），运行期状态（`state/usage.jsonl`、`cache/git.json`、`app.log`）都落在对应配置目录。改 launchd plist 后必须 `bootout` + `bootstrap` 才会重读（`kickstart -k` 只重启进程）。
