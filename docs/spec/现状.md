# cube 项目现状

> 本文件是 cube 项目的**事实快照**——描述当前代码「是什么」，基于代码现状反向提取。
> 与 [`../proposals/`](../proposals/) 的关系：本文件是「现状」，proposals 是「未来要做什么」。
> 维护节奏：每次合并一个有意义变更后同步更新。与代码冲突时以代码为准。

---

## 一、定位

**cube** —— 面向个人开发者的本地项目管理工具（CLI 优先 + 本地 Web）。Go 1.26 编写，module path `cube`。

- 历史有三代：v1 (php)、v2 (go)、**v3 (当前)**。
- 出口：CLI（人用 / alfred）、本地 Web HTTP server（`cube server`，huma + 标准 ServeMux）。MCP 出口为后续规划。
- 定位原则：不做云服务、不绑 AI（cube 可被 AI 编排，但自身不集成 AI）。

---

## 二、分层架构

```
基础设施  config / db / logger / version                            所有层共享
能力      opener / util(git / fuzzy / easycache / pathkit / slicekit / tui)  通用动作, 不含业务实体
领域      project (含 gitcache / scan / clone) / history           业务 domain, 含实体和规则
出口      cmd / web / serve                                           把领域包成 CLI/Web；serve 管 server 进程（fork/探活/关停）
装配      app / main                                                  接线
```

**依赖纪律**：基础设施不依赖上层；能力层只依赖基础设施；领域层依赖能力+基础设施；**cmd 与 web 不互调**；`serve` 依赖 `web`（复用 shutdown 鉴权 header/token）；`app` 是唯一接线点（`app.New(cfg)` 构造整个 App）。

**扩展模型**：加一个新 domain = ①领域包 ②`cmd/<x>` 子命令组 ③`web.NewXxxHandler` ④config 加节 ⑤`app/app.go` 装配清单加构造。五处都是加法，不碰现有 domain。

## 三、关键机制

### 3.1 项目前提：所有项目都是 git 项目

`.git` 存在是扫描判定项目的必要条件（详见 `project/scan.go`）。因此 `tags` 不打冗余的 `git` 标签，只标额外特征（`worktree` / `godot`）。

### 3.2 gitcache 定时刷新

git 项目信息（分支/ahead-behind/dirty 等）缓存在 `~/.config/cube/cache/git.json`。读命令从缓存读快照（几乎零开销），**读路径不阻塞、不触发采集**。

刷新机制按进程类型区分：

| 进程 | 读 git.json | 触发刷新 |
|---|---|---|
| **server**（常驻） | 启动时 Load 一次 | 进程内 goroutine `time.Ticker` 定时 `Refresh`（默认 5 分钟）→ 写内存 + flush git.json |
| **CLI**（短命） | 启动时 Load 一次 | **不刷新**，只读启动时 Load 进来的快照 |

机制要点（`project/service.go` + `project/gitcache/cache.go`，重构记录见 [`docs/archived/260811-gitcache常驻化重构/`](../archived/260811-gitcache常驻化重构/)）：
- **server 定时器**：`Service.StartRefreshTicker` 起 goroutine 跑 `time.Ticker`，启动即刷一次（避免冷启动空窗），之后定时刷新。刷新 = 重扫项目列表（`scanCache.Reload`，毫秒级）→ 按最新路径列表整表采集 git（`gitCache.Refresh`，数十秒级）→ 落盘；`scanUpdatedAt` / `gitUpdatedAt` 分别记录两类数据的新鲜度（web list/info 接口返回，前端分别判断）。装配点在 `cmd/server/start.go`（`app.StartBackgroundJobs` → `server.Start` → `app.StopBackgroundJobs`），CLI 装配不调。
- **单写者模型**：server 是 git.json 唯一写方，CLI 只读不写，无跨进程并发写。落盘靠 `Save()` 的原子写（tmp + rename），无需 flock。
- **git.json 角色**：跨重启持久化缓存——server 重启后秒恢复，CLI 读最近一次落盘（server 没跑时快照可能略旧）。
- **降级优先**：定时器 goroutine 内 recover，采集异常不拖垮 server 进程。
- **采集可观测**：每次 `Refresh` 完成写一条汇总日志（项目数/成功/失败/开始/结束/耗时），排查「缓存为何没更新 / 采集耗时异常」直接查 `cube.log` 这一条。
- **CLI 触发例外**：`cube dev refresh-gitcache`（Hidden 调试命令）可手动触发同一路径的刷新（重扫 + 采集 + 落盘），供开发期实测采集耗时；业务 CLI 命令仍严格只读。

### 3.3 opener role + slotCount

`Opener` 的能力由 `roles []Role` 声明（`open-dir`/`open-file`/`diff-dir`/`diff-file`，见 `opener/role.go`）。`slotCount` 由 role 推导（1 或 2，同 opener 所有 role 必须一致）。`cmd` 中用 `$0/$1...` 占位符引用路径槽位，无占位符时路径追加末尾。

`Open()` 通过 `Executor` 接口执行（`opener/executor.go`），默认实现走 `os/exec`；测试可注入 fake。

### 3.4 App 装配

`app.New(cfg)` 一次性构造整个 App（`app/app.go:26`）：开 db + 跑 AutoMigrate + 构造各 service + 组装 web server。`cmd.Execute()` 在 main 里调用，把 `*app.App` 显式传给所有命令工厂。**无全局单例、无懒初始化**。

### 3.5 配置

默认目录 `~/.config/cube/`，`config.json` 按 domain 分节。`--config` 指定 config.json **文件路径**（dataDir 缺省取其所在目录），`--debug`（`-D`）开 debug（只影响 logger 初始化）。配置文件缺失降级为默认值；JSON 解析失败报错退出；openers 节单条坏配置跳过不阻断（`opener.NewService` 降级）。**无热 reload**（已移除，转向命令式改 config，`config.Save` 提供原子写）。

### 3.6 server 进程管理（HTTP 模式）

server 的进程管理（探活、关停）走 **HTTP 应用层**，不依赖 pid 文件、信号、系统守护。设计背景见 [`docs/archived/260811-server后台常驻与HTTP管理/`](../archived/260811-server后台常驻与HTTP管理/)。

- **探活**：`serve.Status(port)` GET `/api/system/whoami`，验证返回 `app=="cube"` 才算 cube server 在跑（防「别的服务恰好占同端口」误判）。
- **关停**：`serve.Stop(port)` POST `/api/system/shutdown`（带 HMAC 时间戳鉴权，5s 窗口防重放）→ server 自发 SIGTERM → `web.Server.Start` 的信号监听走 graceful shutdown。和 Ctrl+C 同路径。
- **后台启动**：`serve.Fork(port)` fork 自身跑前台 `cube server start`，setsid 脱终端、stdio 丢弃（接 /dev/null，日志走子进程自己 `logger.Init`）。**不写 pid 文件**。
- **允许多实例**：不同端口 = 不同 server，不做全局单实例约束。端口由 `-p` 指定（默认 8080），不进 config。
- **不做 lazy 拉起**：依赖 server 的命令（未来的 md 等）只探测、不自动起，server 由用户显式 `cube server start` 启动（nginx 模式）。

### 3.7 git 访问层：读/写统一走原生 git

`util/git` 是唯一的 git 访问层（历史：v3 早期读走 go-git 库、写走系统 git，双轨；已统一为原生 git）。原因：go-git 的 Status 不加载全局忽略链（与真实 git 输出有偏差）、忽略过滤发生在全量 diff 之后导致大仓库秒级卡顿；原生 git 行为与用户日常 git 完全一致且自带 index 缓存。原「避免 CLI 批量采集 fork 开销」的动机随 gitcache 异步采集（3.2）消失。

- **写操作**（`git.go`，Clone/Push/Commit 等）：stdio 透传，用户看到 git 真实输出。
- **读操作**（`read.go`，Branches/Remotes/Tags/AheadBehind/IsDirty/StatusFiles 等）：只解析机器可读输出（`for-each-ref --format` / `status --porcelain -z` / `rev-list --count` / `symbolic-ref`），不解析任何随 locale 翻译的 stderr 文案。
- **输出稳定化**（`runOut` 统一注入）：`LC_ALL=C` + `GIT_PAGER=cat` 环境变量、`--no-optional-locks`（后台读不抢 index.lock）、`-c core.quotePath=false`（中文路径不转义八进制）；status 显式 `--untracked-files=normal`（覆盖用户 `status.showUntrackedFiles=no`）。
- **非仓库判定**：`isGitRepo` 用 `os.Stat(.git)` 预判——git 报错文案随 locale 变化不可解析，靠预判把「非仓库」（零值降级）与真实错误区分开。
- **错误约定**（原 gogit 包延续）：业务空值场景（非仓库/缺 remote/缺分支）返回零值 + nil；真实读取错误返回 error。gitcache 与 cmd 层依赖此约定。
- **版本基线**：`symbolic-ref` / `for-each-ref --format` 等要求 git ≥ 2.22（2019+，实际开发机 2.29 验证通过）。

## 四、命令列表

入口 `cmd/root.go`，根命令 `cube`。全局 flag `--config`（config.json 文件路径）/ `--debug`（`-D`）用 Go 原生 flag 在 cobra 初始化**之前**预解析（`extractGlobalFlags`）；cobra 上的同名 flag 仅用于 help 提示。

### 一级命令（叶子）

| 命令 | 说明 |
|------|------|
| `version` | 显示版本 |
| `openapi` | 生成 OpenAPI 3.1 spec 到文件 |
| `projects [query] [-g GROUP]` | 项目列表（query 模糊匹配名称；以 `.` `~` `/` 开头时按路径搜索） |
| `info <query> [-v]` | 显示项目信息 + git 快照（分支/ahead-behind/dirty/采集时间，读缓存不实时采集）；git-url 实时展示全部 remote（多 remote 逐行）；`-v` 实时扩展：未提交文件列表、各分支与 remote 差距宽表、cube pull/push 建议命令 |
| `open {project} [--app=]` | 打开项目 |
| `init` | 在指定目录初始化 git 仓库 |
| `clone {repoUrl} [--depth] [-b BRANCH]` | 用 RepoUrl 克隆初始化项目 |
| `openers [query]` | 列出可用 opener（支持模糊搜索） |
| `open-path <path> [-o OPENER]` | 用 opener 打开路径 |
| `diff <path1> <path2> [-o OPENER]` | 用对比工具对比两个路径 |
| `push [仓库路径]` | 批量推送分支/tag 到多 remote |
| `pull [仓库路径]` | 从单个 remote 批量快进更新本地分支（多 remote 时交互单选；当前分支 `pull --ff-only`，其余 `fetch 分支:分支` 快进；默认勾选远端领先分支） |
| `check <options>...` | 检查项目（clone-rules / git-dirty，不传检查全部） |

### 组命令

- **`server`** — 管理 Web HTTP server 的生命周期（进程管理走 HTTP API，详见 3.6）
  - `start [-d|--detach] [-p PORT]` — 启动 server。默认前台阻塞（Ctrl+C 退）；`-d` 后台 fork 脱终端
  - `stop [-p PORT]` — 触发后台 server 平滑关闭（POST `/api/system/shutdown`，HMAC 鉴权）
  - `status [-p PORT]` — 探活（GET `/api/system/whoami`），表格输出状态/端口/版本/访问地址
  - 裸跑 `cube server` = `cube server start`（兼容）。允许多实例（不同端口 = 不同 server），端口默认 8080。
- **`alfred`**（Hidden）— Alfred workflow 集成，输出 Script Filter JSON
  - `project-search {query?}` — 搜索项目
  - `project-open <project-name>` — 打开项目
  - `opener-search [query]` — 搜索 opener
- **`dev`**（Hidden）— 内部调试命令
  - `tui [component]` — 演示 tui 组件
  - `commands` — 列出所有命令
  - `logger` — 测试 slog 输出
  - `refresh-gitcache` — 手动触发 gitcache 全量采集（重扫项目 + 刷新 git.json，实测耗时）

## 五、API 列表

`cube server` 起本地 HTTP 后端（huma）。统一 `ApiOutput{ok, message, data}` envelope，路径强制 `/api/` 前缀。`/docs` 用 Scalar 渲染器，`/openapi.json` 自动生成。当前 **11 个路由**（9 GET + 2 POST）。

### Project（`web/api_project.go`）

| Method | Path | 说明 |
|--------|------|------|
| GET | `/api/project/list` | 项目列表（含 git 快照 + 缓存刷新时间） |
| GET | `/api/project/info?name=` | 项目详情 |
| GET | `/api/project/scan-rules` | 扫描规则 |
| GET | `/api/project/clone-rules` | clone 规则 |
| POST | `/api/project/open` | 用指定 opener 打开项目（body: path + app） |

### Opener（`web/api_opener.go`）

| Method | Path | 说明 |
|--------|------|------|
| GET | `/api/opener/list` | opener 列表 |
| GET | `/api/opener/info?name=` | opener 详情 |

### Config（`web/api_config.go`）

| Method | Path | 说明 |
|--------|------|------|
| GET | `/api/config` | 获取配置 |

### System（`web/api_system.go`）

服务自身的内部管理端点，进程管理走 HTTP 而非 pid 文件/信号（详见 3.6）。

| Method | Path | 鉴权 | 说明 |
|--------|------|------|------|
| GET | `/api/system/whoami` | 无 | 返回 `{app:"cube", version}`，探活方验 `app=="cube"` 确认身份 |
| POST | `/api/system/shutdown` | HMAC 时间戳（5s 窗口） | 触发本进程自发 SIGTERM，走 graceful shutdown |

shutdown 不走 huma 注册（运维端点，不进 OpenAPI 文档），直接挂 ServeMux。鉴权逻辑在 `web/shutdown_token.go`（写死 token + HMAC-SHA256）。

### 静态资源与前端工程

`web/static.go` go:embed 嵌入 `server/web/ui`（构建产物）：`/assets/*` 走文件服务器（StripPrefix + immutable 缓存头），根级文件直出，其余 GET 回 index.html（SPA fallback；`/api`、`/docs`、`/openapi.json` 不参与回退）。

**前端工程在仓库根 `web/`**（Vite + React 19 + React Compiler + TS(tsgo) + Tailwind 4 + Base UI 风味 shadcn + react-router(library mode) + React Query；`pnpm check` = oxfmt + oxlint + tsgo -b）。要点：

- **契约链路**：`pnpm gen:api` = `cube openapi -o openapi.json` → openapi-typescript 生成 `src/api/schema.d.ts`（openapi.json 不入库）；`src/api/client.ts` 在 openapi-fetch 上做泛型分发 + envelope unwrap，业务代码只见纯数据，类型契约由 `client.type-test.ts` 的成对 `@ts-expect-error` 锁定。
- **页面**：`/projects`（列表 + 树双模式，`?view=tree`；筛选/搜索/徽标点击联动；详情抽屉点行滑出）、`/config`（只读）。侧栏底部为工具级入口（Config / API Docs）。
- **构建**：`make build-ui` = `pnpm -C web build` + 拷 `web/dist` → `server/web/ui`；`pnpm run verify:shadcn` 校验 ui 基件与官方 registry 无漂移。

## 六、数据模型

### 6.1 Project 域（`project/`）

- **`Project{path, group, name, tags}`** — path 是绝对路径主键，name = `group:subpath`。git 状态不入实体，由 `Service.GitInfo(path)` 查 gitcache 快照补出。
- **`ScanRule{Group, Path, MaxDepth}`** — 扫描规则。配置层是 `config.ScanRuleConfig`，装配时转为领域层 `project.ScanRule`（做 `~/` 展开）。
- **`CloneRule{RepoHost, RepoPrefix, LocalPath}`** — clone 路由规则，按 host + path 前缀匹配，多条取 prefix 最长者。
- **`gitcache.Entry{RepoUrl, CurrentBranch, DefaultBranch, Branches, Ahead, Behind, Dirty, WorktreeMain, CollectedAt}`** — git 状态快照。

### 6.2 Opener 域（`opener/`）

- **`Opener{name, cmd, roles, slotCount, executor}`** — cmd 用 `$0/$1` 占位，slotCount 由 roles 推导，executor 注入执行。
- **`Role` 枚举**：`open-dir`/`open-file`（slotCount=1）、`diff-dir`/`diff-file`（slotCount=2）。

### 6.3 History 域（`history/`，gorm + sqlite）

两张表（sqlite 文件 `data.db`）：

**`project_select_logs`**（`ProjectSelectLog`）
- `gorm.Model`（id/created_at/updated_at/deleted_at）
- `Project string`、`Alfred bool`

**`project_open_logs`**（`ProjectOpenLog`）
- `gorm.Model`
- `Project string`、`Opener string`、`Alfred bool`

> 注：history 当前**只在 alfred 流程写入**（`cmd/alfred/project_search.go` 写 select、`cmd/alfred/project_open.go` 写 open），CLI/Web 的 open 路径未接入。

## 九、已知 gotcha

- go 源码根在 `server/`（不是仓库根），module path 是 `cube`（README 里写的 `github.com/heyuuu/cube` 是旧值，以 go.mod 为准）；`go build` / `go test` / `goimports` / `go vet` 都要在 `server/` 下跑。
- `.gitignore` 内：`tmp`（构建产物）、`runtime`（测试产物）、`server/web/ui`（`make build-ui` 从 `web/dist` 拷贝后 go:embed 嵌入，改前端改 `web/` 不要直接改它）、`web/openapi.json`（本地生成）、`.zcode/plans` 等 plans 目录。
- 默认配置目录是 `~/.config/cube/`（非项目目录），运行期状态（`data.db`、`cache/git.json`、`cube.log`）都落在那里。
