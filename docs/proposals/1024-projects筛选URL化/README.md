# projects 筛选状态 URL 化

> **状态**：📝 提案（2026-08-24）
>
> **范围**：仅前端（`web/src/pages/projects/`）。
> **独立提案**：与 1025-settings 无依赖关系，可各自实施（1025 的「跳走再回来无损」依赖本提案，但 1025 分期在后，先做本提案即锁定前提）。

## 背景与目标

projects 列表页的搜索词与筛选（group 多选、git 状态单选、tag 单选）目前是组件内 state，导致：

- 刷新即丢：筛出来的列表一刷新回到全量；
- 路由跳转即丢：去别的页面再回来（未来如 `/settings`）筛选重置——这是 1025 settings 讨论中暴露的硬问题；
- 不可分享/不可收藏：本地工具分享场景弱，但「回到上次看的那个筛选」常用。

目标：筛选状态全部收敛进 URL query，刷新/前进后退/跨页往返均无损。

## 方案

- 参数与现有多选/单选按钮一一对应：`q`（搜索词）、`group`（多选，逗号分隔）、`git`（单选：clean/dirty/ahead/behind/none）、`tag`（单选）。空值参数不落 URL。
- 读写统一走 `useSearchParams` 的 `setSearchParams`（`replace: true`，避免每敲一个字压一条历史）；搜索输入做 300ms debounce 再写 URL（输入体验仍走本地 state，URL 是防抖后的投影）。
- 「重置」按钮 = 清空全部参数。
- 默认值变化风险：目前默认即「全选/全部」，URL 化后语义不变（无参数 = 全部）。

## 不做的事

- 不做列宽/排序等其他 UI 状态的 URL 化（有诉求再议）；
- 不做 localStorage 持久化——URL 本身就是持久化。

## 验收标准

1. 筛选任意组合后刷新，列表与筛选按钮状态完整恢复；
2. 跳去其他页面再返回（含浏览器前进/后退），状态无损；
3. `pnpm -C web build` 通过。
