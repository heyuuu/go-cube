# 工作台面板组装：自定义布局 + 面板注册收口

> **状态**：✅ 已完成并验收归档（2026-08-23）
>
> **所属**：[`1008-workspace工作台` 总纲](../1008-workspace工作台/README.md)（先读总纲「已收敛的全局决策」）。
> **依赖**：1011（git 树）、1012（代码阅读）、1013（diff）、1014（PTY）全部完成。**必须最后做**。

## 背景与目标

工作台的长期形态：**同一页面自定义布局**，同屏组合 git 信息、代码、diff、命令行 PTY（例：左 git 树 + 右上代码 + 右下 diff + 底部终端）。1010-1014 期间所有面板跑在基座的固定布局里（左 git 树 + 右内容 + 底部 PTY 抽屉），且从第一天遵守「面板自带数据 hook、只通过 URL 通信」的铁律——本提案把这条铁律兑现成可组装的布局系统。

**本提案不做**：新增任何面板能力、多项目同屏、布局分享导出。

## 实际实现（2026-08-23 验收时回写）

### 1. 布局模型

- **未引入 `react-resizable-panels`**：自研 `PanelSplitter`（flexGrow 比例分栏，可拖拽调宽）+ 面板标题栏 HTML5 原生拖拽换位（`reorderPanel`）。
- 布局持久化：结构化 JSON（`{slots, sizes, slim}`）存 localStorage，key 为 `cube.workbench.layout`，含旧格式兼容迁移。不进 URL（URL 管选中态，布局是个人偏好）。
- 额外增强：面板收窄 `slim` 态（git 树收成窄条）。

### 2. 面板注册表

- `web/src/pages/workbench/panels/registry.ts`：面板注册表（id、名称、组件）。含 `auto` 默认面板——按 URL 选中态自动切 code / diff。
- **同类型面板单实例**：`MAX_SLOTS = 4` 且 `addPanel` 去重；多实例 URL 参数命名空间（`&p1.file=…` 维度）**明确留待需要时再做**。

### 3. URL 状态总线

- `params.ts` 统一读写 `source` / `left` / `right`（`type://id` 序列化），单双选互斥逻辑收口其中。`file` 参数目前由 code/diff 面板直接读写（单实例约束下无冲突）。
- 分享/刷新恢复「选中态 + 面板类型」，布局按接收者本地配置——达成总纲承诺。

## 验收标准

1. 可在页面内添加/移除/移动面板，组合出「git + 代码 + 终端」同屏布局。
2. 布局刷新后保持；URL 分享在对方机器上打开后选中态正确呈现（布局用对方本地的）。
3. 所有既有面板在自定义布局下功能不退化（各面板测试口径回归）。
4. `pnpm -C web build` 通过；前端为本提案主要工作量，后端预计无改动。

## 实施注意

- 本提案几乎纯前端；开始前重读 1010-1014 各面板对 URL 参数与 hook 的约定，收口时不得破坏。
- 拖拽交互注意 Base UI 组件的事件兼容（不用 Radix 生态的 dnd 库写法）。
