Alpine.js · 一个为"无构建链"而生的轻量框架

01它是什么

Alpine.js 是一个通过 HTML 属性驱动交互的极简 JS 库。它的定位很明确：给你 Vue 那样的声明式数据绑定能力，但不需要任何构建步骤——一行 <script> 引进来就能用。

下面这个计数器，整页就是一个真实的 Alpine 组件。点一下试试：

实时演示 · 计数器

当前计数：

它的全部代码就这么几行：

<!-- 引入：一行，defer 必加 -->
<script defer src="alpine.min.js"></script>

<!-- 用法：HTML 属性驱动 -->
<div x-data="{ count: 0 }">
  当前计数：<span x-text="count"></span>
  <button @click="count++">+1</button>
</div>

就这些。没有 createApp，没有 setup()，没有 useState，没有 import，没有 npm install。

02为什么用它（而不是 React / Vue）

三者都能做到上面那个计数器，差别在心智成本和体积。同样一个计数器，三者并排：

Alpine.js 15KB
<div x-data="{n:0}">
  <span x-text="n"></span>
  <button @click="n++">+</button>
</div>

// 一行 script 引入
// 无 import、无构建
Vue 3 45KB
<div id="app">
  <span>{{ n }}</span>
  <button @click="n++">+</button>
</div>

<script>
const { createApp, ref } = Vue;
createApp({
  setup() {
    const n = ref(0);
    return { n };
  }
}).mount('#app');
</script>
React ~45KB
// 需构建链 或 import map
import {useState} from 'react';

function App() {
  const [n, setN] = useState(0);
  return (
    <>
      <span>{n}</span>
      <button onClick={() => setN(n+1)}>+</button>
    </>
  );
}

三个观察：

  • Alpine：数据直接写在 HTML 的 x-data 属性里，逻辑（n++）也在 HTML 里。一个文件搞定。
  • Vue：HTML 写模板，但数据逻辑必须挪到 <script> 的 setup() 里，还要 ref() 包一层。多了一层"模板和 JS 分离"的样板。
  • React：连 JSX 都要编译（或用 import map + htm 字符串），useState + 闭包那套心智最重。
关键差异：Alpine 是"HTML 优先"——逻辑天然内联在标签上，适合页面片段；Vue/React 是"JS 优先"——组件是 JS 函数，HTML 是被 JS 渲染出来的，适合大型 SPA。

07显隐与切换（x-show / x-if）

两者的区别：

  • x-show：通过 display:none 切换，元素始终在 DOM 里。适合频繁切换（抽屉、下拉）。
  • x-if：真正增删 DOM 节点。适合条件渲染（列表里的"无数据"提示）。必须放在 <template> 上。

08实战对比 · 一个"添加输入框"

需求：输入框 + 按钮，点按钮把输入内容加到列表。三者完整对比：

Alpine 15KB
<div x-data="{text:'', items:[]}">
  <input x-model="text">
  <button @click="items.push(text); text=''">
    添加
  </button>
  <template x-for="i in items">
    <div x-text="i"></div>
  </template>
</div>
Vue 3 45KB
<div id="app">
  <input v-model="text">
  <button @click="add">添加</button>
  <div v-for="i in items">{{ i }}</div>
</div>
<script>
const { createApp, ref } = Vue;
createApp({
  setup() {
    const text = ref('');
    const items = ref([]);
    const add = () => {
      items.value.push(text.value);
      text.value = '';
    };
    return { text, items, add };
  }
}).mount('#app');
</script>
React ~45KB
function App() {
  const [text, setText] = useState('');
  const [items, setItems] = useState([]);
  const add = () => {
    setItems([...items, text]);
    setText('');
  };
  return (
    <>
      <input value={text}
        onChange={e => setText(e.target.value)} />
      <button onClick={add}>添加</button>
      {items.map(i => <div>{i}</div>)}
    </>
  );
}

注意几个细节：

  • Alpine 直接操作数组 items.push()，响应式自动生效。Vue 在 setup 里要写 items.value.push()（多一层 .value）。React 必须用 setItems([...items, text])（不能直接 push，状态不可变）。
  • Alpine 的 text='' 清空直接写在 @click 表达式里。React 要单独调 setText('')。
  • 代码行数：Alpine ~6 行模板、Vue 14 行、React 13 行（且要编译）。

11三者取舍（一句话版）

Alpine.js ✓
适合：
- 无构建链、纯 HTML
- 页面片段、表格、抽屉
- 个人工具、后台型
- 渐进增强已有页面

不适合：
- 大型 SPA（多路由、深嵌套）
- 需要强类型 TS + 组件树
Vue 3
适合：
- 中等复杂度应用
- 想留升级 Vite+SFC 后路
- 喜欢 setup() 显式响应式

不适合：
- 极轻量场景（45KB 偏大）
- 完全不想写 JS 样板
React
适合：
- 大型 SPA、团队协作
- 复杂状态、生态依赖
- 已有 React 肌肉记忆

不适合：
- 无构建链（JSX 要编译）
- 轻量交互（hooks 心智重）
cube 的判断：本地工具、几十个项目、表格+抽屉+git 徽章、不要构建链——这是 Alpine 的教科书场景。Vue 可作次选（功能全但偏重），React 不匹配（要构建、心智重）。

12为何 Alpine 适合 cube（对应到具体页面）

把 cube 的前端需求逐条对应到 Alpine 特性：

  • 项目列表表格 → x-for 循环 + :key。见第 06、09 节。
  • git 状态徽章（clean/dirty/ahead） → :class 动态绑 class。见第 09 节。
  • 搜索框 → x-model 双向绑定 + getter 算过滤。见第 04、09 节。
  • group 筛选下拉 → x-model + getter。见第 09 节。
  • 点行滑出详情抽屉 → x-show + x-transition。见第 07、10 节。
  • Tab 切换（project / config 域） → x-show。见第 07 节。
  • fetch 后端 JSON → init() 钩子里调 fetch，见第 09 节。
  • 30s 自动刷新（拉 gitcache 快照） → init() 里 setInterval(this.load, 30000)。

Alpine 的几个"坑"提前知道

  • x-data 的 {} 是对象字面量，不能直接写复杂逻辑。复杂组件用 x-data="myComponent()"，把函数定义放到 <script> 里（cube 会大量用这种，见第 09 节的 getter 写法）。
  • x-for 和 x-if 必须挂在 <template> 上，不能直接挂普通元素（和 Vue 一样）。
  • defer 必加：Alpine 必须在 DOM 解析完后初始化，所以 <script defer>。
  • 没有虚拟 DOM：更新是直接操作真实 DOM。性能上几十到几百个元素完全够用，但上千行表格就该上虚拟化了（cube 量级远不到）。
什么时候该换 Vue/React：如果 cube 前端膨胀到「多路由 SPA + 组件嵌套深 + 需要强类型 TS + 团队多人协作」，就该升级到 Vue+Vite 或 React+Vite。Alpine 的 x-data 函数可以无痛迁移成 Vue 的 setup()——数据模型几乎一一对应，迁移成本主要在把 HTML 属性改成模板语法。
